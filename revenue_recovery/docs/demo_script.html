How it decides

Say

"The loop is Detect, Diagnose, Decide, Guard, Act, Measure. Detect scores risk and how much is actually recoverable. Diagnose finds the root cause — plain rules first, an LLM only as fallback for messy free text. Decide is a deterministic policy table: same inputs, same intervention, every time — fully auditable. Guardrails run after that and can only make things more conservative — downgrade a discount, force a human escalation — never add contact the policy didn't ask for. The LLM's only job in this whole loop is writing the customer-facing message."

Show

Common pitfalls
  • Don't wait on camera for run_batch. With a live LLM key configured, Gemini's free tier caps at 5 requests/min, so a 240-event batch can run well past a minute. Pre-run it and show the finished scorecard instead.
  • Don't read every guardrail reason by name. Point at the panel, say the count, move on — the visual is doing the work.
  • Don't narrate the tech stack. FastAPI, Pydantic, SQLite are implementation detail; judges are scoring the loop and the audit trail, not the framework choices.
  • Move the cursor slowly and deliberately. Fast mouse flicks are hard to follow at recorded frame rates — pause on each thing before naming it.
